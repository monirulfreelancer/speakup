# SpeakUp Android app (Trusted Web Activity)

This folder wraps the deployed SpeakUp site as an Android APK using
[Bubblewrap](https://github.com/GoogleChromeLabs/bubblewrap). The APK is a
thin shell: it opens the live website fullscreen in Chrome's engine. All
features (mic included — Chrome handles the permission prompt inside the app)
come from the deployed site, so most updates need **no new APK at all**. You
only rebuild when the domain, icons, name, colors or shortcuts change.

App id: `io.speakup.app` — reverse-domain style, chosen for a future
speakup.io/app.speakup.* domain; it is independent of whatever web domain the
app points at, and MUST never change (Android treats a new id as a different
app).

## Files

| File | What it is | In git? |
| --- | --- | --- |
| `twa-manifest.json` | The single source of truth. **The host lives at the top of this file** | yes |
| `speakup-release.keystore` | The signing key — the app's permanent identity | **NEVER** (see SIGNING.md) |
| `.keystore-pass` | Keystore + key password | **NEVER** |
| `fingerprint.txt` | SHA-256 of the signing cert (public) | yes |
| `build.sh` | The whole rebuild, one command | yes |
| `app/`, `build/`, `gradle*` | Generated by Bubblewrap — disposable | no |

## Rebuilding after a domain change

1. Edit `twa-manifest.json`: replace the host in `host`, `webManifestUrl`,
   `fullScopeUrl`, `iconUrl`, `maskableIconUrl` and the two shortcut
   `chosenIconUrl`s (search the old host — it appears nowhere else).
2. Make sure the new domain serves `/.well-known/assetlinks.json` with the
   fingerprint from `fingerprint.txt` (it is baked into
   `src/app/.well-known/assetlinks.json/route.ts`, so it moves with the site
   automatically).
3. Run:

   ```bash
   cd android
   ./build.sh
   ```

4. Commit the updated `twa-manifest.json` and `public/downloads/speakup.apk`,
   push, and redeploy the web app.

Already-installed apps keep working during a domain move only if the OLD
domain keeps redirecting; realistically, ship a new APK and tell testers to
reinstall.

## Rebuilding for a version bump

1. In `twa-manifest.json`, increase `appVersionCode` by 1 (Android refuses to
   install an update with the same or lower code) and set `appVersionName` /
   `appVersion` to the human-readable version.
2. Update `APP_VERSION` in `src/app/download/page.tsx` to match.
3. `cd android && ./build.sh`, commit, push, redeploy.

## First-time machine setup

Everything is local to this folder except Bubblewrap's own toolchain:

```bash
cd android
npm install                 # installs @bubblewrap/cli (devDependency here, not in the web app)
npx bubblewrap doctor       # first run offers to download its JDK + Android SDK — answer Yes
./build.sh
```

The keystore and `.keystore-pass` must be restored from backup first — see
`SIGNING.md`.

## Verifying the fullscreen association (Digital Asset Links)

If the installed app shows a Chrome address bar at the top, the asset link
check failed. Confirm:

```bash
curl https://<host>/.well-known/assetlinks.json
```

must return JSON whose `package_name` is `io.speakup.app` and whose
`sha256_cert_fingerprints` matches `fingerprint.txt` exactly. You can also
paste the URL into Google's checker:
`https://developers.google.com/digital-asset-links/tools/generator`.
After fixing it, force-stop the app (or wait — Android re-checks
periodically) and reopen.

## APK vs AAB

`build.sh` produces both. **Only the APK matters for direct download** from
the /download page. The AAB (`build/speakup.aab`) exists solely for a future
Play Store upload and can be ignored until then.
